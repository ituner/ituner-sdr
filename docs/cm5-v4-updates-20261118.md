# CM5 live changes collected on 2026-11-18

This PR consolidates the CM5 application and V4 support changes since the
2026-11-05 synchronization to main (`4616f40`). Source was read from the running
installation, not the stale `/home/ituner/ituner-sdr` checkout. No live application
restart, settings change, or hardware output change was needed to collect it.

## Behavior

- V4 volume and zoom mechanical encoders use quadrature decoding and button
  debouncing; the smooth volume control uses the increased sensitivity.
- Optical tuning uses all 1,440 edges per turn. AUTO follows visible span:
  Fine 2.5%, Normal 25%, Coarse 100% per revolution. MANUAL uses the selected
  tune step with independent 0.1x / 1x / 4x sensitivity and fractional-Hz
  accumulation. Clockwise increases frequency.
- Mode, Band, Map, Mute and Scan use the existing UI actions. PTT is inert.
  Display is mapped but was not physically verified in the original session.
- Public and Trusted Local tuning profiles default to 5 and 50 commands/second.
  Both sliders span 1–100 and save independently. A receiver must be explicitly
  marked Trusted Local. Kiwi audio and waterfall share one budget; OpenWebRX
  and FM-DX use the same pacing layer. Pending positions coalesce, while local
  display updates remain independent and keepalives bypass tuning limits.
- The compact tuning sidebar keeps mode and sensitivity separate; the main
  frequency font is 60 rather than 36.
- DISPLAY includes persistent 5–100% PWM backlight brightness.
- Audio hardware work moves off the UI thread. ADS-B history only rebuilds for
  an actively requested view, yields during batches and avoids copying/sorting
  the complete initial history twice. Reception and logging continue hidden.
- The waterfall follows measured incoming row cadence, with a bounded jitter
  reserve and catch-up. Diagnostics report stalls and actual pacing.
- V4 display/touch reset, amplifier/headphone and external USB power mappings
  are preserved as source and configuration. See the
  [V4 profile](../hardware/cm5/v4/README.md) for wiring and deployment.

The app source in this PR matches the live snapshot. Repository-only additions
adapt the saved tests to repository paths and demand-driven coverage, document
the profile, and make audio/USB setup preserve V4 wiring. Personal receiver
state, credentials, generated recordings, build products and backup copies are
not part of the change.

## Validation

The isolated checkout was tested on CM5 with Python 3.13 and kernel
`6.18.50+rpt-rpi-2712`. Tests use temporary state and fake hardware/transports. They do not exercise
new physical button presses, change the radio's receiver, or claim fresh
end-to-end checks of every receiver protocol.

- Application suite: 279 tests, 274 passed. All 60 newly collected tests passed.
  Five failures/errors reproduced on unchanged main: three ADS-B native-view
  tests use an incomplete text-cache mock, and two board-layout expectations
  disagree with existing Display controls / dual-VFO mode ordering.
- Hardware/setup suite: 19 tests passed, including V4 USB boot migration and
  idempotence, existing audio interlocks/configuration, and appliance checks.
- Panel module built against the running kernel headers. The V4 PWM/display/
  touch DTBO compiled without diagnostics and applied offline to the CM5 base
  device tree. Neither the module nor DTBO was installed during PR preparation.
- Changed Python sources compiled; shell syntax and `git diff --check` passed.

## November 19 follow-up

A separate follow-up PR adds the internal USB host-mode correction and
context-sensitive ADS-B zoom routing. The V4 USB setup helper now preserves
backups of both boot files and removes conflicting peripheral/serial-gadget
configuration. The live correction was applied and rebooted successfully:
the onboard hub and a downstream RTL2832U both enumerate. The user confirmed
that the brief observed disconnect was their own unplugging.

The physical zoom knob now follows the active ADS-B view: map clicks use the
same 1.6x factor as the on-screen buttons; coverage clicks change zoom by 25
percentage points, bounded to 50–400%. Other ADS-B pages and modal input do not
change a hidden radio zoom. Returning to radio retains the existing waterfall
zoom behavior. The routing reuses the existing view handlers and limits.

Follow-up validation: 26 knob/encoder/tuning tests and 25 CM5 hardware/setup
tests passed on CM5, including nine new ADS-B routing tests and six USB-host
configuration/backup/idempotence tests. The two updated application files were
checked against the live baseline before installation, backed up, then installed
with an application restart. The USB helper was tested against temporary boot
files; no second reboot was needed for packaging the already applied USB fix.
